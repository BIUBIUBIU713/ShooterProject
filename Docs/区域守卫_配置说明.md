## 行为树结构改动

从 BT_ShooterEliteMeleeEnemy / BT_ShooterEliteRangedEnemy 各复制一份，命名为 BT_RegionMeleeGuard / BT_RegionRangedGuard。
从 BB_ShooterEnemy 复制 BB_RegionGuard，两个新树都选择此 Blackboard Asset。
下面表示对原树的插入位置，原攻击、追击和待机分支保持原来的内部结构。

```text
ROOT
└─ Selector
   │ 【服务】移除原 Shooter BTService Player Target（标题 Update Player Target）
   │ 【服务】添加 Update Guard Target（C++ 类 ShooterBTServiceGuardTarget）
   │         Interval=0.2；Random Deviation=0；Call Tick on Search Start=勾选
   │         固定读写 TargetActor、HasLineOfSight、IsInAttackRange、
   │         GuardHomeLocation、GuardReturning；不需要选择 Blackboard Key
   │ 【服务】其余原有服务保留，原来的 TargetActor 配置保留
   ├─ Sequence（新增，放到最左边）
   │  │ 【装饰器】Blackboard：Blackboard Key=GuardReturning
   │  │           Key Query=Is Set；Notify Observer=On Result Change
   │  │           Observer Aborts=Both
   │  ├─ Move To【任务】Blackboard Key=GuardHomeLocation
   │  │         Acceptable Radius=50
   │  │         Reach Test Includes Agent Radius=不勾选
   │  │         Reach Test Includes Goal Radius=不勾选
   │  │         Allow Partial Path=不勾选
   │  │         Observe Blackboard Value=勾选
   │  └─ Wait【任务】Wait Time=0.2；Random Deviation=0
   └─ 原有所有执行分支按原顺序放在右侧
      远程树：原 Sequence、Sequence、Wait；不是再加一个 Selector。
      近战树：保留复制来的攻击与追击分支，Random Melee Attack 的 Attacks 不重填。
```

服务和装饰器通过节点的附加菜单添加，不占执行子节点的位置。
更新守卫目标服务必须挂在 ROOT 下的 Selector 上，覆盖返岗和战斗的全过程。
不要同时保留 Update Player Target，否则它会重新给返回岗位的守卫设置玩家目标。

### 黑板新增键

| Key Name | Key Type | 说明 |
|---|---|---|
| GuardHomeLocation | Vector | 每名守卫首次执行服务时记录自己的出生位置 |
| GuardReturning | Bool | 正在返回岗位，返岗期间不重新接敌 |

原 TargetActor(Object/Actor)、HasLineOfSight(Bool)、IsInAttackRange(Bool) 保留。

### Update Guard Target 初始建议值

| 属性 | 区域近战 | 区域远程 |
|---|---:|---:|
| Acquire Radius | 1200 | 2400 |
| Leash Radius | 1800 | 3000 |
| Home Acceptance Radius | 150 | 150 |
| Interval | 0.2 | 0.2 |

单位厘米，均以出生岗位为中心。玩家进入 Acquire Radius 且无遮挡时接敌；接敌后允许继续追击至 Leash Radius。
玩家或守卫超出追击范围后清除目标并返回岗位。返回途中忽略重新接敌，回到岗位后才重新判断。
这是对目标与距离的限制，不是碰撞围栏：服务每 0.2 秒更新，路径绕行也可能短暂跨过范围边缘。
新远程树中原 Update Attack Range 仍为 2400；原可见追击 Move To 的 Acceptable Radius 仍为 1800。
返岗的 Move To=50，与 Home Acceptance Radius=150 配合，避免到达导航目标后仍一直判定未回到岗位。

## 地图生成器

放置 C++ 类 RegionGuardSpawner，每个区域一个。也可以基于它建立 BP_RegionGuardSpawner（区域守卫生成器）再放入地图。
通过放置 Actor 搜索 Target Point，为每名守卫布置一个点；不要使用回合系统的 EnemySpawnPoint。
TargetPoint 放在角色胶囊中心高度，位于可行走导航区域；点之间留出胶囊间距，避免墙体、门和障碍。

| 属性 | 首次验证设置 |
|---|---|
| Region Id | 与选定区域门当前的 Door Group Id 完全一致，不要猜测地图实际值 |
| Spawn Trigger | Region Unlocked |
| Guard Count | 5 |
| Ranged Guard Count | -1 表示默认 40%；兵营使用 Guard Count=6、Ranged Guard Count=4 |
| Melee Guard Class | BP_RegionMeleeGuard |
| Ranged Guard Class | BP_RegionRangedGuard |
| Spawn Points | 5 个元素，各选择一个不同的 TargetPoint |
| Retry Interval | 0.5 |
| Max Spawn Attempts | 20 |

一个区域有多扇联动门时，它们使用同一个 DoorGroupId，区域解锁广播只发一次。
独立门如果当前 DoorGroupId=None，也要填一个唯一标识，才能关联生成器。
生成器位置不决定守卫出生位置；守卫分别使用 Spawn Points，类型随机分配但数量固定。
Ranged Guard Count=-1 时，远程人数=总人数×40% 四舍五入，剩余给近战。例如总数 1→1近0远，2→1近1远，5→3近2远，10→6近4远。
Ranged Guard Count 设为 0 到 Guard Count 之间的值时，直接使用指定远程人数；兵营当前为 6 人中 4 远程、2 近战。
Spawn Points 数量至少等于 Guard Count，只使用前 Guard Count 个。

Spawn Trigger=Begin Play 表示下一帧开局生成；Manual 需要其他代码或蓝图调用 Trigger Spawn。
Trigger Spawn 返回 true 仅代表本次请求被接受，不代表所有守卫都已经生成成功。
每个生成器每局只接受一次有效请求。失败槽位自动重试，成功槽位不会重新生成。
当前撤离系统尚未接线，Manual 为后续撤离触发预留。

## 运行验证

1. 先验证一个区域：未解锁时没有守卫，解锁后日志出现 Guards triggered，total=5 melee=3 ranged=2。
2. 结合五条 Guard spawned 确认实际生成完成；计划日志不能证明全部成功生成。
3. 再交互同组入口不重复生成，不再次扣款；本波 WaveManager 计数不包含这些守卫。
4. 玩家进入警戒范围且可见时接敌；超出追击范围后日志 returning=1，守卫返岗，回到岗位后 returning=0。
5. 五名守卫均击杀后仅出现一次 Guards cleared；直接 Destroy 守卫不视为击杀。
6. 玩家死亡后停止未完成的生成重试。新开一局可再次触发。

Guards cleared 只提供事件，目前不打开撤离门；撤离门继续保留 Boss 击败条件。
代码错误或出生碰撞导致少生成时，不会把该组误判为清理完成，需查看 Error 日志并修正配置。
