## 2. 面向"玩法程序员"岗位的亮点清单

面试官看作品，关心"你做了什么系统、怎么实现的、踩了什么坑"。本项目按以下顺序展示亮点：

| 亮点 | 具体内容 | 面试能展开讲的点 |
|---|---|---|
| ① 战斗手感 | 后坐力/散布/准星、换弹节奏、爆头判定、命中反馈 | 射线检测流程、骨骼命中、数值手感调优 |
| ② 玩法系统 | 轮次状态机、分数经济、交互物接口（IInteractable）、开门解锁 | 状态机设计、接口解耦、经济平衡思路 |
| ③ 数据驱动 | 武器/僵尸/轮次/门价全部走 DataTable | 改数值不改代码的好处、配表结构设计 |
| ④ AI | 行为树追击/近战/受击硬直/死亡消散 + 轮次缩放 | 黑板键、任务节点、难度爬升控制 |
| ⑤ 工程能力 | GameMode/Controller/角色分层、存档（USaveGame）、Enhanced Input | 职责划分、存档时机、输入系统 |

> 讲法建议：每个亮点准备 2 分钟"实现 + 为什么这么做 + 踩了什么坑"的讲述。

## 5. README 模板（可直接套用）

```markdown
# ShooterSamProject — 第一人称僵尸生存原型（UE 5.7）

基于 Unreal Engine 5.7 用 C++ 实现的第一人称僵尸生存玩法原型：
无尽波次、分数经济、墙购武器与地图解锁，目标是"活得更久"。

[▶ 演示视频](视频链接) | [📷 截图](docs/screenshots)

## 玩法
- 击杀僵尸获得分数（命中 +10 / 击杀 +60 / 爆头 +100 / 刀杀 +130）
- 分数购买武器（墙购）、开门解锁新区域
- 僵尸逐轮变强：数量、血量、速度按 DataTable 配置爬升
- 倒地即结算：展示生存轮次 / 击杀 / 爆头 / 总分

## 操作
WASD 移动 · Shift 冲刺 · 空格 跳跃 · 左键 射击 · R 换弹 · F 刀 · E 交互 · 1/2 切枪

## 技术亮点
- **玩法系统**：轮次状态机（ZombieGameMode）、分数经济、IInteractable 交互物接口（门/墙购）
- **武器**：数据驱动的 WeaponBase（弹药/换弹/后坐力/散布/爆头倍率），数值全部在 DataTable
- **AI**：行为树僵尸（追击/近战/受击硬直/死亡消散），轮次缩放驱动难度
- **工程**：GameMode/Controller 分层、USaveGame 轮末自动存档、Enhanced Input

## 如何运行
1. 安装 UE 5.7（本机路径 D:\UnReal\UE_5.7）
2. 打开 ShooterSamProject.uproject → 打开 `Content/Zombies/Maps/Lvl_Zombies`
3. 点击 Play（或打包 Shipping 版本）

## 目录结构
- Source/ShooterSamProject/Zombies/ — 核心 C++
- Content/Zombies/ — 地图与蓝图
- Docs/ — 设计文档与包装计划

## 致谢
第三方资产来源（角色模型 / 音效 / 特效）……
```

## 7. 面试可能问题与准备

| 问题 | 准备方向 |
|---|---|
| 为什么做僵尸模式？ | 喜欢玩法驱动的设计 + 能同时展示战斗/AI/经济/UI 多个系统 |
| 轮次系统怎么设计的？ | 状态机（开始→生成→战斗→轮末），生成节奏与数量上限 |
| 僵尸 AI 为什么用行为树？ | 状态少、可配置、好调试；对比过 StateTree 的取舍 |
| 难度怎么控制？ | 轮次缩放表（数量/生命/速度公式），DataTable 驱动 |
| 分数经济怎么平衡的？ | 前期手枪够用、中期必须买武器、门价与收益节奏对齐 |
| 遇到的最大技术难点？ | 准备 1~2 个真实踩坑故事（如 NavMesh 烘焙、FP 模型、命中判定） |
| 数据驱动的好处？ | 改数值不改代码、策划可配、AB 测试方便 |
| 如果时间更多会加什么？ | 展示规划能力：Perk 机 / PaP / 合作模式 / 世界分区大图 |
